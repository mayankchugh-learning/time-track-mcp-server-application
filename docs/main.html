01 — Purpose

What this file is (and is not)

TimeTrack is one idea: billable hours in SQLite, readable by a person over HTTP and by an assistant over MCP. This file is the mounted production shape: curated tools first, then FastAPI with the MCP lifespan, then /static and /mcp.

This file · main.py
Curated @mcp.tool first. http_app(path="/") plus mount("/mcp"). Prompt + timesheet://projects. One process, two doors.
Learning file · main_to_understand.py
FastAPI first. from_fastapi copies every route into tools. Extra raw SQL. mcp.run() for STDIO. Nothing mounted at /mcp.
Official FastMCP docs make the same split: generate an MCP server from FastAPI, versus mount an MCP server into FastAPI. You are on the second path — the one you ship.

You need a sibling database.py (init_db, list/log/summary/timesheet). You do not need execute_query. Production never calls it. Rebuild context: LEARNING_AND_REBUILD.md.

03 — Block A

Imports and startup

db.init_db() runs when the module is imported, so the table exists before the first request. That is simple and fine for this size. It is not a migration system.

from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse
from pydantic import BaseModel
from fastmcp import FastMCP

import database as db

db.init_db()

StaticFiles and FileResponse are used here. The learning file imports StaticFiles and never uses it — that file never serves a website.

04 — Block B

Curated MCP first

mcp = FastMCP("TimeTrack") — tools are not generated from OpenAPI. You write each one. Names default to the function names. Clients call log_time, not api_log_entry.

start_date: str = "" then start_date or None. MCP clients send strings more happily than null. The SQL date filters stay optional.
Docstrings are the API
The model reads them to decide when to call a tool. Write entry_date must be YYYY-MM-DD, not a comment for humans only.

There is no list_all_entries tool. The website needs a dump of every row. The assistant does not. REST can be wider than MCP — that is least privilege in a small file.

list_projects (tool) and known_projects (resource) share db.list_projects(). Two primitives, one query. A tool is “go fetch names.” A resource is “here is the vocabulary — reuse Website Redesign.”

A prompt does not query SQLite. Auto-wrap cannot invent it. Interview line: auto-wrap copies HTTP; curated tools add behavior HTTP never had.
05 — Block C · the part people get wrong

http_app + lifespan at construction

mcp_app = mcp.http_app(path="/")

app = FastAPI(title="TimeTrack", lifespan=mcp_app.lifespan)
PieceCorrectWrongSymptom
http_app pathpath="/"path="/mcp"Client hits /mcp/mcp
FastAPI lifespanFastAPI(lifespan=...)set after app exists/mcp never initializes
app.mount("/mcp", mcp_app) already adds the prefix. Setting http_app(path="/mcp") as well doubles up into /mcp/mcp — a real, easy-to-miss bug.

FastMCP’s HTTP app owns a session manager. Passing lifespan=mcp_app.lifespan into the constructor is how uvicorn starts and stops it. Assigning app.router.lifespan_context later is too late: the website works, the client connects and immediately dies.

MCP first is not ideology. You cannot pass lifespan=mcp_app.lifespan before mcp_app exists. Construction order is the constraint.
06 — Block D

REST, website, mounts

Each handler is a one-liner into database.py. REST does not own SQL. The browser never talks to MCP — static/app.js only fetches /api/*.

The MCP tool does not use NewEntry. Same fields, two schemas, one db.log_time.

@app.get("/")
def serve_index():
    return FileResponse("static/index.html")

app.mount("/static", StaticFiles(directory="static"), name="static")
app.mount("/mcp", mcp_app)

Declare GET / before the mounts. Mounts are prefix catch-alls.

uv run uvicorn main:app --reload --host 127.0.0.1 --port 8000
Website / · Swagger /docs · MCP /mcp

Swagger lists REST only. Tools are not FastAPI paths. Optional: uv run fastmcp inspect main.py:mcp — four tools, one resource, one prompt.

07 — Shape

Two objects, one database

Person ──HTTP──► FastAPI app   ──┐
                                  ├── database.py ── SQLite
Assistant ─MCP─► FastMCP mcp  ──┘

app is what uvicorn serves. mcp_app is the FastMCP HTTP ASGI mounted at /mcp. mcp is the tool/resource/prompt registry. They share data only because both call db.*. There is no hidden bus.

Preferred habit: database.py first, doors second. The website and the assistant are clients; database.py is the application.

Same row, two doors

  1. Browser POST /api/entries → NewEntry → db.log_time → table refresh.
  2. Assistant calls log_time → same db.log_time → open / and the row is there. No websocket.
  3. Weekly-report prompt returns recipe text → model calls get_timesheet → empty week says so, does not invent hours.
08 — Names

What the model actually sees

People in Swagger think in paths. Models think in tool names. You chose log_time, get_timesheet, timesheet://projects, generate_weekly_report.

The learning file after from_fastapi typically yields api_list_projects and api_log_entry — HTTP names leaking into the tool list. You did not choose those; OpenAPI did.

Why you ship this file

  • You choose tool names and docstrings. HTTP details stay on /docs.
  • Four tools. No generic SQL interpreter. REST may list all entries; MCP does not have to.
  • Streamable HTTP at /mcp on the same process as the website.
  • Tools exist before http_app; lifespan is set at construction.
  • Prompts and resources cannot be generated from REST.

Quiz

Q1. http_app(path="/") means the MCP endpoint is /. True or false?

False. path="/" is inside the mounted sub-app. app.mount("/mcp", mcp_app) puts it at /mcp.

Q2. uvicorn main:app — can a browser call log_time? Does Swagger list it?

The three-tab website never calls it — only /api/*. Swagger lists REST only. log_time is an MCP tool, not a FastAPI path.

Q3. Why start_date="" on MCP but start_date=None on REST?

Query params can be omitted. Many MCP clients send empty strings more easily than null. "" or None is None, so the SQL bound is skipped.

Q4. A prompt is a SQL query. True or false?

False. A prompt returns instructions. Tools (or REST) touch the database.

Q5. You set lifespan after FastAPI() exists. What breaks?

The MCP session manager never starts. /mcp fails quietly; the website still works. Pass lifespan= into the constructor.

Q6. Delete the resource, keep list_projects. Why invent “website redesign”?

A tool is an action the model may forget to call. A resource is advertised as current vocabulary. Without it, the model guesses spelling.

When you can draw app vs mcp vs mcp_app, explain /mcp/mcp and lifespan-at-construction, and say why a prompt is not SQL — rebuild Phases 5–7 without looking, then study the contrast file.
