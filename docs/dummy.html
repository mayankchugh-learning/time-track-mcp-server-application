01 — Purpose

What this file is (and is not)

dummy.py answers one question: what is the least you can ship as an MCP server? Import FastMCP, create mcp = FastMCP("Calculator"), decorate five functions, stop. Horizon imports mcp.

This file · dummy.py
Arithmetic only. No FastAPI. No SQLite. Entrypoint dummy.py:mcp. Use it to prove Horizon can import a FastMCP object.
Class deploy · mcp_server.py
Same decorator shape, but each body calls database.py. Horizon form for TimeTrack is mcp_server.py:mcp.
Production app · main.py
Imports that mcp object, wraps http_app, mounts /mcp next to a website. Never the remote entrypoint.
Official FastMCP docs split three paths: generate MCP from FastAPI, mount MCP into FastAPI, or run MCP alone. This file is the third path — the one Horizon is built for.

Inspect it: uv run fastmcp inspect dummy.py:mcp. You should see five tools, no resources, no prompts. Local Inspector: uv run fastmcp dev dummy.py.

03 — Block A

The docstring is the deploy card

Entrypoint: dummy.py:mcp is Python import syntax written as a form field.

dummy.py   →  the module Horizon imports
mcp        →  the FastMCP object that module must leave in its global namespace

If you renamed the instance to server, the form would be dummy.py:server. Horizon inspects that object at import time. Side effects that need a running event loop, a missing ./static folder, or a FastAPI mount fail the build. That is why main.py is the wrong entrypoint.

uv run fastmcp inspect dummy.py:mcp — five tools. No timesheet:// URIs. If you see TimeTrack names, you pointed inspect at the wrong file.
04 — Block B

The whole server

mcp = FastMCP("Calculator") — the constructor string is the in-process server label. The Horizon Server name field is a different string and becomes the public hostname. They can differ.

Docstrings are the API
The model reads them to decide when to call a tool. Change add’s docstring, re-run inspect, find your text.
Type hints are the schema
float here is enough. You do not write an OpenAPI spec. Tool names default to the function names.

There is no resource and no prompt. Arithmetic does not need a vocabulary URI or a weekly-report recipe. Those appear in TimeTrack because hours have names that must stay consistent.

if b == 0:
    raise ValueError("Cannot divide by zero.")
return a / b
A string return looks like success. An exception is a tool error. The host can show it and the model can change b. Do not paper over bad input with a happy-path sentence.
05 — Block C

mcp.run() is a local door

if __name__ == "__main__":
    mcp.run()

This runs only when you execute the file. Importing the module — Horizon, fastmcp inspect, fastmcp dev — does not call mcp.run().

How you start itTransport
uv run python dummy.pySTDIO
uv run fastmcp dev dummy.pySTDIO + Inspector UI
uv run fastmcp run dummy.py --transport httpStreamable HTTP on a port
Horizon dummy.py:mcpPublic Streamable HTTP
Default mcp.run() is STDIO. Putting it at module top level (no if __name__) hangs the import. That trap is why main_to_understand.py is careful about where the first mcp.run() sits.
06 — Names

What the model actually sees

People in Swagger think in paths. This file has no Swagger. The model sees tool names you chose: add, subtract, multiply, divide, power.

Ask a connected client: “What is 12 divided by 4, then raise that to the power of 3?” It should call divide then power — two tools, not one clever local calculation it invents. Same discipline TimeTrack wants: use the server, do not invent hours.

08 — Practice

Do these, then quiz yourself

  2. Change the add docstring. Re-run inspect. Find your text.
  3. Call divide with b=0 from Inspector. Confirm you get an error, not a number.

  5. Write one sentence: why main.py is the wrong Horizon entrypoint and dummy.py is a valid smoke test. Then open main.html.

Quiz

Q1. Horizon runs if __name__ == "__main__": mcp.run(). True or false?

False. Horizon imports the module and takes the mcp object. The if __name__ block is for local STDIO only.

Q2. The entrypoint is dummy.py. True or false?

False. The form is dummy.py:mcp — module plus the FastMCP instance name. dummy.py alone is a file, not an object.

Q3. Why does divide raise ValueError instead of returning a string?

A string return looks like success. An exception is a tool error the host can surface so the model changes b.

Q4. You run python dummy.py. Can a browser open /docs and try add?

No. Default mcp.run() is STDIO. There is no FastAPI app and no Swagger.

Q5. Why deploy dummy.py before mcp_server.py on a new Horizon account?

If the calculator comes up, Horizon, GitHub, and the entrypoint syntax work. A later TimeTrack failure is about SQLite, not “can Horizon import FastMCP.”

Q6. FastMCP("Calculator") must match the Horizon Server name. True or false?

False. The constructor string is the in-process label. The form Server name becomes the public hostname. They can differ.
