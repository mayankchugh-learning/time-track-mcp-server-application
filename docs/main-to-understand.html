01 — Purpose

What this file is (and is not)

TimeTrack is one idea: billable hours in SQLite, readable by a person over HTTP and by an assistant over MCP. This file is the walkthrough style: write a normal API, wrap it as MCP, then compare that to hand-curated tools left in comments.

This file
FastAPI first. from_fastapi copies every route into tools. Extra raw SQL. mcp.run() for STDIO. Nothing mounted at /mcp.
Production main.py
Curated @mcp.tool first. http_app(path="/") plus mount("/mcp"). Prompt + timesheet://projects. One process, two doors.
Official FastMCP docs make the same split: generate an MCP server from FastAPI, versus mount an MCP server into FastAPI. You are on the first path only.

You need a sibling database.py (init_db, list/log/summary/timesheet, and execute_query). If it is missing here, copy it from the complete TimeTrack pack or rebuild Phase 2 of LEARNING_AND_REBUILD.md.

02 — Map

The file in four blocks

Python executes top to bottom at import time. That fact explains every trap later.

B

C

Raw SQL tool + resource timesheet://schema. Not REST. Easy to never register — see the trap.
D

StaticFiles is imported and never used. This learning file never serves a website.

03 — Block A

REST first

db.init_db() runs when the module is imported, so the table exists before Swagger loads. Each handler is a one-liner into database.py. REST does not own SQL.

MethodPathDatabase call
GET/api/entrieslist_all_entries()
GET/api/projectslist_projects()
GET/api/projects/{project}/summaryget_project_summary(project)
GET/api/timesheet/{employee_name}get_timesheet(...)
POST/api/entrieslog_time(...) via NewEntry

Only api_list_all_entries has a docstring. After auto-wrap, that text becomes the tool description. The other four leak names like api_list_projects with almost no help for the model.

NewEntry is defined after the GET routes and before POST. That is legal: Python only needs the class when the decorator runs. FastAPI uses it for JSON validation and for the Swagger form.

The comment in the file says -reload. The real flag is --reload. Port 9998 keeps this off production 8000.
uv run uvicorn main_to_understand:app --port 9998 --reload
# http://127.0.0.1:9998/docs

Uvicorn serves app. It does not start mcp.run(). Swagger will not show /mcp.

04 — Block B

from_fastapi builds a second object

from fastmcp import FastMCP
mcp = FastMCP.from_fastapi(app=app)

if __name__ == "__main__":
    mcp.run()

from_fastapi does not add routes to app. It reads the OpenAPI spec and creates MCP tools (every endpoint, by default).

CommandWhat startsClient sees
uvicorn …:app --port 9998FastAPI ASGIREST + /docs
python main_to_understand.pymcp.run() (STDIO)MCP over a pipe
A GET to http://127.0.0.1:9998/mcp is a FastAPI 404. This file never mounts. Generation and mounting are two different integrations.
05 — Trap

mcp.run() before extra tools

mcp.run() is a blocking server loop. It does not return. When you start the file as a script:

  1. Build FastAPI routes
  2. from_fastapi
  3. mcp.run() — process sits here forever
  4. execute_query_dynamically — never registered
  5. timesheet://schema — never registered
  6. Second mcp.run() — dead code

Uvicorn imports the module, so both if __name__ blocks are skipped. Block C still runs at import time. The in-memory mcp object then has the extra tool — unused, unless you later call mcp.run() or mount it.

Keep one mcp.run() at the bottom of the file. The first if __name__ is the lesson, not a style to copy.
06 — Block C

SQL tool + schema resource

These are not REST routes. They exist only on mcp.

Tool · execute_query_dynamically
The model invents SQL. Demo-friendly. Unsafe to ship: DROP TABLE, inflated hours, prompt injection. Also brittle if _row_to_dict expects time_entries columns.
Resource · timesheet://schema
Pullable context, not an action. Hand-written DDL snapshot — stale if the table changes. Production uses live timesheet://projects instead.

MCP primitives: a tool does something, a resource is context, a prompt guides the next tool calls. Least privilege means you expose log_time / get_timesheet / summaries — not a database root shell.

07 — Block D

The commented production pattern

Uncomment these in your head. They are what production main.py ships.

KindNameWhy
Toollog_timeInsert; docstring requires YYYY-MM-DD
Toolget_timesheetEmpty strings become None so date filters stay optional
Toolget_project_summaryAlready grouped for speech
Toollist_projectsDistinct names
Resourcetimesheet://projectsSame list, as context, so spelling stays stable
Promptgenerate_weekly_reportRecipe: call get_timesheet, group, do not invent hours
A prompt does not query SQLite. Auto-wrap cannot invent it. That is the interview line: auto-wrap copies HTTP; curated tools add behavior HTTP never had.
08 — Names

What the model actually sees

People in Swagger think in paths. Models think in tool names. Auto-wrap typically yields api_list_projects, not list_projects.

Person ──HTTP──► FastAPI app  ──┐
                                 ├── database.py ── SQLite
Assistant ─MCP─► FastMCP mcp ──┘

Preferred habit: APIs (or database.py) first, MCP second. Do not mutate working OpenAPI just to get nicer tool docs. FastAPI and FastMCP are different products that happen to compose.

Why you do not ship this file

  • HTTP names leak; you cannot combine two APIs into one tool.
  • Raw SQL violates least privilege.
  • No /mcp mount for Streamable HTTP beside the website.
  • Startup order can drop later primitives.
  • Prompts cannot be generated from REST.
09 — Practice

  1. Move the first mcp.run() to the bottom. Predict whether Inspector lists execute_query_dynamically. Check.
  2. Add a docstring to api_list_projects. Inspect the generated tool description.
  3. Sketch REST POST /api/entries vs curated log_time. Same db.log_time, different names.

Quiz

Q1. from_fastapi adds /mcp to the FastAPI app. True or false?

False. It builds a separate FastMCP instance. /mcp appears only if you mount mcp.http_app(...).

Q2. uvicorn …:app — is execute_query defined? Can a browser call it?

Defined: yes (uvicorn imports the whole file and skips mcp.run()). Browser: no. Uvicorn serves app, not mcp.

Q3. python main_to_understand.py as committed — does the schema resource register?

No. The first mcp.run() blocks before @mcp.resource runs.

Q4. Why invent “website redesign” with auto-wrap but not with timesheet://projects?

Auto-wrap does not give a live list of canonical names. A resource that returns list_projects() does.

Q5. A prompt is a SQL query. True or false?

False. A prompt returns instructions. Tools (or REST) touch the database.
